# 0.3.2: opt-in Metal improvements and PyTorch operator preview

This release makes the retained Metal optimizations available through a
SDK-compatible receipt executable. It also introduces `vitni-torch` 0.1.0a1,
an experimental package exposing two explicit PyTorch operators. The Rust
core's numerical regime and published anchors are unchanged. Rejected research
prototypes remain inactive fixtures/patches.

## Optimized Metal engine

Build from a tagged checkout on macOS with Cargo and Metal available:

```sh
cargo build --release --manifest-path metal/Cargo.toml --bin vitni-receipt-metal
./metal/target/release/vitni-receipt-metal --optimized \
  --gguf model.gguf --prompt "1,2,3" --n 8 --model-id example
```

`--optimized` (or `VITNI_METAL_OPTIMIZED=1`) enables this retained configuration:

```sh
VITNI_METAL_Q4K_VARIANT=metadata
VITNI_METAL_RMS_COOPERATIVE=1
VITNI_METAL_RMS_VARIANT=no_contract
VITNI_METAL_Q6K_COOPERATIVE=1
VITNI_METAL_ATTENTION_COOPERATIVE=1
VITNI_METAL_CONCURRENT_DISPATCH=1
```

Set `VITNI_RECEIPT_BIN` to the absolute executable path and
`VITNI_METAL_OPTIMIZED=1` before importing Vitnify to use this with the existing
SDK. Alternatively pass the executable to `Engine(..., binary=...)`.
The CLI returns the CPU CLI's JSON schema: both digest versions, numerical
regime, model weights hash and generated tokens.

The preset's latest lower-load matched TinyLlama forward time was 1.256647286 s
against 0.510426452 s for ordinary llama.cpp/Metal, a **2.462x** ratio (rounded
in discussion to 2.47x). This is the existing 108-step finite-model experiment,
not a fresh performance campaign or an end-to-end application guarantee.
It excludes model load, startup and receipt construction. Full evidence and
the unsuccessful fusion confirmation are in
[the confirmation report](../metal-swiglu-low-load-confirmation.md).
That run compared 12,416,000 raw logit words per mode against pinned CPU
files with no mismatches across three TinyLlama histories and a Stories
fallback history.

The release smoke test used Vitnify SDK 0.4.9's actual `Engine.run` bridge.
Optimized Metal and CPU produced identical complete JSON for TinyLlama
(prompt `[1,450,11781,338]`, four generated tokens) and Stories (prompt
`[1,2,3]`, eight generated tokens). The over-context rejection was also tested.
These smoke tests establish integration, not speed.

Limits: this CLI rejects contexts beyond `min(model_context,512)`, dimensions
outside the current Metal tiles, and projection encodings other than
Q4_K/Q6_K/Q5_0/Q8_0 with valid block widths. It does not silently change the
model configuration to fit. The pre-existing Metal SiLU division edge for
exponential overflow remains unresolved; finite-model agreement is not a
universal IEEE-754 guarantee. This release did not retest physical CUDA,
other Apple GPU generations, larger models or long contexts.

## PyTorch preview

Build/install with Rust/Cargo and Python available:

```sh
python -m pip install '.[torch]'
# or, from any directory after the tag is published:
python -m pip install 'vitni-torch[torch] @ git+https://github.com/vitnify/vitni-tensor@v0.3.2'
```

The GitHub release provides a macOS ARM64 wheel and source archive. This
preview is not published to PyPI. Requires PyTorch 2.14+; tested locally with
2.14.1 on an M3 Max, Python 3.12.11. See [the operator guide](../../python/README.md)
for use and the exact contract.

CPU calls the Rust engine; MPS directly dispatches the engine's Metal shaders
on MPS tensors. Nothing overrides `torch.matmul` or global Torch settings.
Both operators are inference-only, contiguous float32; `q4_k_linear` accepts
raw uint8 GGUF Q4_K rows. CUDA, gradients and arbitrary model conversion are
not implemented.

Each floating input must be zero or have magnitude in `[2**-32,2**32]` on
both devices; unsupported values are rejected using integer bit inspection.
K is limited to 64 chunks of 8192. This restriction matters: the actual
PyTorch MPS shader path flushed the minimum subnormal in the compiler probe,
despite source safe-math controls. The package reports this probe and rejects
the unsupported domain rather than claiming arbitrary float32 equivalence.

The installed wheel passed **39 tests on actual CPU and MPS**, including:

- Independent scalar canonical reduction and GGUF decoding references;
  zero extents, lane/chunk tails, cancellation inputs and storage offsets.
- Exact integer-bit CPU/MPS comparisons, repeated GPU execution, and a test
  that forbids the Rust CPU loader during MPS execution.
- `torch.library.opcheck`, full-graph compile with eager/AOT-eager/Inductor,
  and export/save/reload for both operators on both devices.
- Rejection of unsupported layouts, types, sizes, gradients, numerical
  domains, nonfinite Q4 results and altered CPU flush-to-zero state.

Five real captured Q4_K projections from TinyLlama and Stories also matched
the pre-existing pinned CPU outputs: **10,272 output words per device**, zero
bit mismatches. All referenced input files were checked against their prior
SHA256 provenance. This is operator coverage, not a whole PyTorch model.

### Component costs

The general float32 operator has not had the specialized full-model engine's
optimization work. Twelve alternating repetitions included validation,
allocation and device synchronization, with transfers excluded. Native
PyTorch may calculate different bits. These are local medians, not portable
speed guarantees:

| Device | M,K,N | Vitni | native `torch.matmul` | ratio |
| --- | --- | ---: | ---: | ---: |
| CPU | 4,256,16 | 0.0436 ms | 0.00152 ms | 28.7x |
| CPU | 32,512,64 | 0.4535 ms | 0.00331 ms | 136.9x |
| CPU | 1,2048,2048 | 10.0609 ms | 0.17617 ms | 57.1x |
| MPS | 4,256,16 | 1.3939 ms | 0.30892 ms | 4.51x |
| MPS | 32,512,64 | 0.9005 ms | 0.20654 ms | 4.36x |
| MPS | 1,2048,2048 | 1.7194 ms | 0.23946 ms | 7.18x |

First-call measurements (including compilation) and raw repetitions are in
[the machine-readable evidence](../research/torch-preview-2026-11-13.json).
Validation synchronizes MPS and adds substantial fixed cost. These figures
must not be replaced with the full-model engine's 2.47x ratio.

Reproduce installed-package checks and component timings:

```sh
python -m pip install '.[torch,test]'
VITNI_REQUIRE_MPS=1 python -m pytest -q python/tests
python python/examples/benchmark.py --output benchmark.json
```

Without `VITNI_REQUIRE_MPS=1`, CPU-only environments explicitly skip GPU
coverage. CI builds source/wheel packages and runs CPU contract tests on
Linux and macOS; GPU evidence here comes from the physical local M3 Max.

Research evidence uses `<workspace>/` in place of the original machine-specific
absolute prefix. Numeric observations and referenced content hashes are unchanged.
